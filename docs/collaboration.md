# 子智能体协作闭环

`0.1.0-dev.14` 在 `.10` 只读协作树上增加由产品拥有的委派账本，以及创建、暂停、继续、核对和交回主任务。OpenCode 仍是唯一模型与工具执行路径；星杳没有复制调度器，也不修改上游数据库。

## 身份与责任边界

- 产品任务持久化的 OpenCode 根 `sessionId` 是协作树信任边界。
- 创建委派前从公共 `GET /agent` 读取角色，只允许非隐藏且 `mode=subagent` 的角色。当前固定引擎公开 `explore` 和 `general`。
- 产品创建的子会话写入 `metadata.xingyao={kind:"delegation",delegationID,taskID}`，并固定根会话、标题和 agent。每次控制前重新读取会话并核验全部身份字段。
- 不带该身份、身份冲突或由 OpenCode 自行产生的子会话只读显示，不能被产品认领、暂停、继续或交回。
- 子会话消息不自动写入主聊天、记忆、经历、情绪或技能证据。工具摘要也不证明主任务完成。
- 交回主任务必须明确选择一条已完成的 assistant 消息。服务器重新读取完整历史并核对来源，再把它作为有边界的未验证材料提交给根会话。根会话输出仍进入普通验收流程。

## 持久状态与失败恢复

schema 5 的 `delegations` 表保存产品委派 ID、幂等键、任务/根/父/子会话身份、agent、当前说明、状态修订、消息基线、是否尝试交付及显式交回来源。schema 4 升级只增加空表，既有历史记录不改写。

创建会话和发送说明都是不可安全重试的写操作：

1. 创建响应丢失后，不再次 `POST /session`。系统在根会话的直接 children 中按持久 metadata 查找唯一匹配；找不到或出现多个匹配时保持待核对。
2. 发送说明前保存完整消息 ID 基线，并在请求前持久标记已尝试交付。响应丢失后只读取完整历史，按新消息判断是否落盘，不重新发送。
3. 继续操作使用同一个子会话和新的幂等键、基线及状态修订，不创建新会话。
4. 应用重启把 `creating/running/stop_requested` 降为待核对。不会自动恢复模型调用或工具操作。
5. 暂停调用公共 abort。它只表示 OpenCode 接受停止请求；此前发生的工具副作用不会被描述为已撤销。

委派任务会阻止检查点、模型重配置、睡眠整理和普通安全退出跨越正在进行的请求。强制退出仍先停止产品拥有的引擎，再等待委派任务收束。

## 公共 HTTP 接口

适配器仅使用：

```text
GET  /agent
POST /session
GET  /session/:sessionID
GET  /session/:sessionID/children
GET  /session/:sessionID/message
POST /session/:sessionID/message
POST /session/:sessionID/abort
GET  /session/status
```

协作树仍限制为 32 个子会话、4 层、单个历史响应 1 MiB、页面正文投影合计 2 MiB、整次读取 15 秒。重复 ID、循环、错误 parentID、跨会话消息、非法时间、分页历史和未知状态都会失败关闭。

浏览器只收到消息正文与来源 ID，以及工具名、调用 ID、适配器核验的生命周期/结果、可验证的退出码和时间。工具输入、原始输出、任意上游错误、状态私有字段与认证元数据不进入协作响应。动态内容用 DOM `textContent` 渲染。

## 当前限制

- 子智能体的执行质量、成本与工具权限仍取决于所选 OpenCode 模型和配置。权限请求在主对话页与协作页显示，产品不会自动批准。
- 暂停后的实际文件或外部系统状态需要主任务核对；abort 不是事务回滚。
- 一次交回选择一条已完成 assistant 消息；较长正文投递给主会话时最多保留 16000 字符并明确标记截断。
- GitHub Codex 聊天档案尚未自动包含产品运行时的 OpenCode 根会话和子会话；这需要独立、有界、去敏的导出通道。
- 兼容性绑定固定 engine.6-source 的公共协议。上游更新必须重新执行真实 agent、所有权 metadata、父子树、历史、停止及编译产品验收。
