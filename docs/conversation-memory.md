# 有来源、可审阅的对话记忆

`0.1.0-dev.8` 的对话记忆流程是：原始对话 → 有引文的候选 → 人工核对 → 有范围和有效期的记忆。模型输出只进入候选表；没有审阅不会创建长期记忆，更不能改人格或扩大工具权限。

## 输入、判断与审阅

每批最多取同一任务 20 条原始消息、24,000 字符，另附最多 30 条当前有效公开记忆、8,000 字符。不截断单条原话；首条超长时需要人工拆分。来源必须同时匹配聊天 ID、正文、角色、来源 key 和学习策略。私密来源、被撤回来源、封存期间产生的经历不发送。

模型每批最多提 8 条候选，要求逐字引文、主体、归属、类型与原文时间提示。只有助手原话的候选必须保持“推断”，不得作为事实；JSON、字段、枚举和来源验证失败会拒绝整批。机器校验不能证明语义理解正确：真实引文仍可能被模型曲解，所以人工必须核对否定、人物、时间和条件。

审阅者选择长期或明确日期范围、是否私密、是否固定，以及新增或替代同范围记忆。提交携带候选修订和本次审阅所见的整体数据修订；并发变更返回冲突，界面保留草稿并要求重新核对。日期范围包含所选结束日，存储为次日零时的失效边界。浏览器草稿尚未持久化。

替代偏好保留当年的原话，只让旧偏好退出当前使用；纠正错误事实沿用来源撤回机制。过期和未来记忆仍可管理，但不会参与上下文，包括固定记忆。当前检索仍是词项检索，已补齐混合查询中的独立汉字匹配；没有实现语义向量。

## 后台执行与睡眠

固定 OpenCode 公共 HTTP 接口创建专用后台 session，设置 deny-all；不复用前台 session。普通文本承载 JSON，省略上游 `format` 和旧 `tools` 参数。历史核对要求一个用户输入和完整助手响应，任何工具尝试都拒绝。公开 history 与 session 身份、权限一致性检查不能省略。后台消息不进入前台对话、工具经历、情绪或技能。

提取请求的总适配器期限为 60 秒，创建和清理另有较短期限。超时、中断、网络失联不重发模型 POST。收到 session ID 后先记录归属再发送资料；结束后核实删除及两个公开读取接口 404。清理失败保留 pending，后续空闲仅重试清理。未完成批次在重启后标为 interrupted，不自动推理。

自动提取默认关闭；启用后应用需运行并空闲 5 分钟，每次维护最多启动一批，默认滚动 24 小时 4 批，可设 1–12。手动和失败批次也占用后续自动额度；待审候选达到 64 条时停止自动启动（正在完成的一批最多另加 8 条）。手动提取不受自动额度限制。失败或被打断的任务需手动新 key 重试；这避免反复付费。批次额度并非金额或模型内部循环次数的硬上限。

前台新对话优先取消并等待后台工作收敛。封存同时改变 epoch，阻止封存再解封期间的旧输出落库。检查点和模型重配置等待后台结束；退出先中断后台并等待清理尝试，然后保存状态。来源删除使候选擦除，在途结果不能复活。

## 数据迁移与已知限制

Schema 3 新增候选批次、候选表和记忆 claim。升级在工作副本中进行并增加领域修订；schema 1/2 历史检查点保持原字节。旧程序不能打开 schema 3；回退需选旧程序配套的历史检查点。数据库版本升级不等于原生 OpenCode 引擎升级，两者仍分别遵守兼容报告。

临时提取 session 在删除前仍持久存在于引擎。如果创建请求已落库但响应丢失，产品可能未取得其 ID；当前不能声称完全没有孤立 session。它尚未收到对话资料，仍需后续按公共 API 和作业归属实施恢复扫描。删除已有记忆也不删除历史检查点、原始文件或前台 OpenCode 原生会话。

当前候选页面只展示选定任务最近 100 批（最多 800 条候选），没有长期档案分页；候选和批次数据库尚无保留期限。自动提取限额减少积累，但不能替代 90 天容量测试。当前知识图谱仍展示资料链接和来源关系，不自动推断人物关系。

## 验证的含义

领域和 HTTP 测试使用临时 SQLite 身份，检查真实事务、修订、回滚、来源擦除、有效期、后台取消和检查点。真实引擎测试与浏览器测试使用固定 exe 和本地确定性模型，验证协议、权限及产品流程。`evals/conversation-memory-zh.json` 有 24 个中文人工预期，用于后续真实模型对比；夹具通过不代表模型提取准确率已达标。

完整发行门禁还会执行实际升级与恢复、编译启动、知识图谱/文件浏览器和本次审阅界面。测试报告必须绑定当前制品哈希；云端 Actions 执行与本地执行分开记录。
