## 本轮解决的问题与验收内容

- 普通旧检查点不能直接由新引擎恢复，现有宿主此前又能绕过恢复版本校验直接启动另一 exe。本轮加入显式隔离迁移及同宿主版本/hash 绑定；离线模型设置、模型重配置和失败恢复不能绕过绑定。
- SQLite 只读连接可能创建原库的 WAL/SHM。迁移前检查改为复制领域库及辅助文件后再打开副本，避免检查本身改动原件；真实测试保留逐文件哈希和存在性断言。
- 真实旧引擎夹具包含 4 个产品任务、2 个唯一会话、重复绑定、未绑定任务和带来源记忆；旧历史包含文本、读取成功、读取拒绝及 shell exit 7。迁移摘要保留公开 API 的全部原始字段。
- 在恢复来源、旧引擎验证、新引擎启动、历史核对四个发布前边界注入失败，没有发布新完整代次，原宿主和旧检查点保持原字节。迁移过程没有发送模型请求。
- 成功后形成唯一后继检查点。正常 `main()` 从干净旧宿主接续这个新代次，身份、任务与记忆不变，目标引擎真实健康检查通过；退出生成正确父子关系的新配套代次。
- 新配套检查点与原旧检查点分别恢复后，都通过产品任务 HTTP 接口继续同一任务并触发新的读取权限；旧 exit 7 仍被解释为失败。旧副本没有混入新版续接消息。
- 单独构造仅存在于 WAL 中的未同步提交；主库字节未变，迁移仍识别到新修订并拒绝，所有原始数据库、WAL/SHM 和便携库保持不变。

## 当前限制

验收针对上表两个准确制品、legacy HTTP、稳定项目路径与本地确定性模型。它不承诺未来 OpenCode 版本天然兼容。每个新候选仍须重新验证；V2 API 未实现。

迁移摘要覆盖产品已绑定会话，不涵盖所有未登记子会话、无绑定会话或外部附件文件。无一键升级 UI、迁移暂存清理策略或真实断电证明。已安装身份本轮未迁移；`.5` 的安装选择经再次读取确认。完整 V2 中的中文记忆质量、持久草稿/编辑崩溃恢复、长期容量、子智能体 UI 与 Infinite Canvas 仍需继续。

GitHub API 再次核实：默认分支为 `conversation-archive`，没有 Release、Actions 运行记录或 Actions 变量。本地 workflow 的历史基准消费路径已准备，首次云端构建仍需发布准确 engine.5 测试资产并配置基准 tag；产品源码尚未推送。详见 [GitHub 使用方案](github-product-workflow.md)。
