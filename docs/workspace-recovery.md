# 编辑草稿与保存恢复

`0.1.0-dev.9` 使用 schema 4。目录选择仍然只在当前进程有效；重新启动后选择原目录，可找到同一路径的持久草稿。旧版程序拒绝打开 schema 4，回退需要匹配的旧发行和旧配套检查点。

## 草稿和文件各自保存什么

编辑器在输入停顿约 400 毫秒后提交草稿。服务器确认后，正文保存在本机身份数据库，随成功检查点备份；不会自动写入项目文件、知识库或记忆。确认前的最后输入可能仍只在页面中，关闭页面会提示。应用内切换文件或页面时先等待草稿确认，失败则保留编辑。

再次打开文件时，界面先展示磁盘正文，让使用者明确恢复或丢弃草稿。磁盘版本变化需要对照、合并并确认基础版本，随后才能保存文件。两个窗口通过修订号检测竞争；迟到的保存、删除或重试不能静默替换新草稿。成功写入文件后只清理同一修订的草稿，另一个窗口的新稿保留。

草稿最多 32 份，总正文最多 16 MiB，单份 UTF-8 正文最多 2 MiB。容量满时拒绝新写入，保留已有内容，不自动淘汰。删除保留修订墓碑，避免迟到请求复活旧稿。列表提供只读正文，即使原项目整目录暂时不可用，也可以复制恢复。此入口读取当前身份内的草稿，不授权访问任意磁盘路径。

## 中断保存的恢复依据

保存时在项目根 `.xingyao-edit-*` 保留原文、拟写内容和阶段记录；宿主数据库旁的 `workspace-recovery` 保存同一操作的可信记录。仅当两处记录一致、目录和文件身份及内容可验证时才自动恢复。选择项目目录时进行核查，也可以在恢复面板重试。

- 原件已归档而目标尚未发布：以独占创建和复制恢复原件，保留全部副本。
- 拟写内容已完整落盘且证据一致：补全提交记录。
- 目标、父目录或记录被其他程序修改，或者恢复复制中断后不能证明完整性：保留冲突，供人工核对。
- 当前仍有保存进程持有文件锁：显示忙碌，稍后重试。

恢复后的知识索引只刷新已导入的资料，保留范围和私密属性，并再次核对当前内容仍等于这次可证明的恢复结果。历史保存记录不会使后来外部修改的内容自动进入知识库。外部编辑仍应在知识库明确刷新。

F 盘 exFAT 上重命名可能改变文件标识，因此实现通过持有文件句柄证明重命名前后的连续性，并记录新标识；恢复不依赖硬链接。

## 当前边界

草稿进入身份检查点；项目原件、拟写副本和宿主可信恢复记录不随此检查点搬到另一台电脑。换机或丢失宿主记录后，旧保存日志进入人工核对。备份目录与阶段记录尚无自动清理；草稿墓碑、领域 outbox 也尚无长期压缩策略。

每个项目恢复列表最多扫描 5000 个根目录条目、返回 200 条恢复记录，超限会提示截断。后续需要根据真实使用容量增加索引和保留策略。文本框仍有大量短行的性能边界。

故障测试覆盖真实进程突然退出、竞争和冲突保留。Windows 下 Node 无法对目录执行 fsync，真实断电、控制器缓存与突然拔盘尚未验证；记录缺失或两边不一致时保守留待人工核对。文件身份检查与协作锁也不构成针对恶意本机进程的操作系统沙盒。

测试使用临时身份和目录，包括实际 F 盘 exFAT 的隔离目录。具体计数、浏览器结果和制品哈希见对应发行验收报告。
