## 建议的仓库结构

```text
main                         产品源码主线，逐步取代聊天分支作为默认入口
  src/                       运行时、公开接口适配器、工作台
  test/                      领域、恢复、真实引擎及编译产品回归
  patches/opencode/          上游基线、必要补丁、哈希与退出条件
  script/                    构建、验收、安装及迁移验证
  docs/                      架构、实际能力、已知限制、发行证据
  evals/                     后续中文长期记忆任务和评分依据
  .github/workflows/         后续自动检查与候选构建
conversation-archive         已有可导出聊天档案，独立保留
feature/*、fix/*              有范围的修改，通过 PR 进入主线
```

当前源码本身适合一个产品仓库。无需为了文件、图谱、睡眠和人格各建一套独立仓库。完整 OpenCode 修改若需长期维护，可单独维护一个引擎 fork，并由产品 manifest 固定源码提交、构建方式、版本和 SHA-256；本产品仍通过 `adapter.ts` 对接公开接口。

## GitHub 功能与实际用途

| GitHub 能力 | 用于本产品 | 合格条件 |
|---|---|---|
| Git / PR | 代码、数据结构变更、必要引擎补丁的审阅历史 | 每项变更解释触发条件、行为变化、验证与迁移影响 |
| Issues / Milestones | 把架构缺口拆成可验收任务 | 用可复现输入和通过标准描述，避免只写“更聪明” |
| Actions | Windows 类型检查、结果链测试、恢复测试、候选构建 | 真实引擎和编译产品测试必须执行，跳过不能等同发行通过 |
| Releases | 携带引擎的便携包、哈希、变更说明、兼容表 | 制品绑定源码和真实通过报告，保留上一合格版本 |
| 上游候选 PR | 评估 OpenCode 新提交、修复补丁冲突、继续旧会话 | 在隔离副本验证数据迁移与恢复；通过后才成为可选更新 |
| conversation-archive | 按用户要求保留主任务与子智能体的可导出记录 | 脱敏、来源范围、截止时间与文件哈希明确 |

## 自动化前需要补齐的工程条件

1. **完整引擎构建来源。** 现有 `patches/opencode/manifest.json` 固定了上游基线和两组已验证补丁，但 README 已明确：旧产品工作树的其他修改不在这两份补丁内。现在不能承诺“克隆上游、应用两个补丁即可复现 engine.5”。必须整理完整 fork 提交及依赖锁，或逐项剥离旧改造，才能在干净 GitHub runner 上重新构建同一功能集合。
2. **消除开发机路径依赖。** `script/build.ts` 的上游许可证默认路径、浏览器验收中的 Edge 路径来自当前 Windows 电脑。CI 应传入明确的引擎与许可证路径，使用被固定和验证的浏览器安装；缺少真实制品时应直接失败。现有 `bun.lock`、Bun 1.4.2 与源代码哈希可作为可重复构建的基础。
3. **分开普通检查与发行门禁。** 普通 PR 可先做类型和领域测试；Windows 候选任务负责实际引擎、配套恢复、独立编译入口和浏览器测试。发行门禁沿用 `script/verify-release.ts` 的零失败、零跳过、制品哈希匹配要求。
4. **补项目发布说明。** 根 README 应先介绍实际可用版本和启动方式，随后说明未完成能力；项目许可证与第三方许可一起维护。大型可执行文件放 Release assets；凭据、活动数据库、便携快照和媒体资料采用各自存储流程。
5. **升级只生成候选。** 上游更新可以触发检查，但不能仅因补丁能套用、HTTP health 正常就切换用户引擎。合格升级需要旧会话续接、失败/超时结果、数据迁移、崩溃恢复、旧版本配套恢复的实际证据。

## 开源组件如何进入这个流程

| 组件 | 保持的职责 | 集成记录 |
|---|---|---|
| OpenCode | 模型会话与工具执行引擎 | 固定源码/制品、最小必要补丁、公开接口与迁移回归 |
| Cytoscape.js | 文件、知识和记忆关系的浏览 | 本地打包固定版本；关系事实、修订和删除仍由领域库管理 |
| Infinite Canvas | 图片、视频及视觉方案编排 | 单独模块；先落实媒体资产、任务/取消、凭据接口和便携保存 |
| Graphiti / LightRAG | 候选记忆抽取或资料检索增强试验 | 先在隔离中文评估集比较收益，再决定是否增加服务依赖 |

所有组件进入仓库前都应记录上游地址、固定版本/提交、许可证、使用的接口、数据持久化方式与替换条件。详细选型依据见 [工作台模块与开源选型](workbench-modules.md)。
