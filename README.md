# 星杳 · 璇玑

星杳是温暖、有主见、稳定的专属助理；璇玑是承载她的 Windows 便携工作系统。本项目把身份、经历、情绪、记忆、知识和经验保存在独立运行时中，通过版本适配层使用 OpenCode 执行任务。

当前源码版本：`0.1.0-dev.5`，本地开发预览；已安装版本及验收依据见 [验证记录](docs/verification.md)。完整架构见 [系统设计](docs/system-design.md)，实施进度见 [能力清单](docs/implementation-status.md)；本文件只描述当前实现。

## 使用

验收安装后，从 U 盘根目录双击 **启动星杳.cmd**。浏览器会打开仅监听本机的工作台。

1. 在「系统中心」填写 OpenAI 兼容接口地址、模型 ID 和 API 密钥。保存成功表示本地引擎接受了配置；发送一个简短任务后再确认远端模型可用。配置保存在这台电脑的用户应用目录；更换电脑需要重新连接模型。
2. 在「对话与任务」交代工作。工具需要授权时，选择允许这一次或拒绝。模型回答结束后任务进入待验收，检查成果后确认完成。
3. 「记忆」可以保存偏好、事实和承诺，纠正后相关旧结论会失效。私密记录默认不传给模型。
4. 「知识库」导入明确选定的 UTF-8 文本、Markdown、CSV 或代码文件。搜索支持中文，结果带原始路径与行号。单文件当前上限 2 MiB。
5. 「睡眠整理」归档已验证的工具经历，重复执行不重复学习。程序运行且空闲 5 分钟后，也会按 100 条事件的限额增量整理。
6. 「经验技能」可从真实工具结果提出有适用条件的方法。至少三个独立结果满足验证门槛后才能启用；撤回来源会使经验进入复核状态。
7. 「文件管家」先生成清单，再按分类移动文件。原件保存在该目录内的 `.xingyao-recovery-<计划ID>` 以供撤销，不自动清理。整理和撤销会更新已导入资料的引用路径。
8. 离开前在「系统中心」选择保存并退出，确认检查点完成、程序退出后再由 Windows 弹出设备。关闭浏览器标签页不等于退出程序。

「知识图谱」提供已导入资料的目录树、文件链接与记忆来源关系。按项目范围、私密标记、类型和文字筛选，选中节点可展开当前已加载的相邻关系；点击节点或连线可查看导入版本正文与实际来源。正文分页显示原始行号。图谱来自保存的资料快照，源文件修改后需在知识库刷新导入，才能更新图谱。此资料树不代表整个磁盘的文件浏览器。

图谱使用本地打包的 Cytoscape.js 3.34.3；基础浏览不需联网。当前只展示明确的 wiki/Markdown 文件链接及记忆的经历来源，未自动推断人物与语义关系。图谱查询有数量上限，界面显示截断与未解析链接；局部视图只覆盖已加载数据。视觉创作将通过独立 Infinite Canvas 模块接入。

`.5` 修正工具结果到情绪、睡眠和经验的证据链：shell 非零退出记为失败，超时或缺失退出码记为未知；工具返回不能自动代表整项任务完成。重复修订替换有效证据，旧来源保留历史且不重复计入。承诺默认固定，固定记忆超过上下文预算时明确停止发送。数据库迁移为 schema 2；旧 schema 1 检查点保留，并在恢复后迁移。旧程序不能直接使用新版数据库。修复范围与限制见 [证据修复说明](docs/evidence-fixes-2026-09-17.md)。

模型配置中的密钥不会返回浏览器、写入记忆或随领域检查点备份。配置目前保存在宿主用户目录的 JSON 文件中，未实现便携加密凭据库。

## 连续身份与存储

运行中的数据库在 `%LOCALAPPDATA%/Xuanji/<driveId>/`，U 盘保存经过哈希与 SQLite 完整性校验的代次。每个完整代次可以同时包含星杳状态与 OpenCode 会话数据库；凭据和缓存不在引擎备份白名单中。

Windows 使用 `SUBST` 建立稳定工作路径。首次选择可用盘符，并记录在 `Xuanji/drive.json`。再次启动优先使用同一盘符；如果该盘符被其他设备占用，启动会明确拒绝，避免把历史任务指向错误目录。当前数据和旧启动器保留。

界面显示未同步变化。意外拔盘前最后一刻的变化可能只保存在宿主；程序不会把缺少完成清单的快照当成可恢复代次。多个分支或未知锁会阻止自动覆盖，需要明确处理。

记忆删除会清除独立运行时中的修订、来源正文、关联工具/聊天副本和相关技能，并保留删除标记防止同源结果被再次导入。**已经存在的备份、OpenCode 原生会话和用户原始文件不由这个按钮删除**，界面会说明范围。缓存正文被清除时，操作幂等身份仍保留，防止曾经执行过的操作被重复发起。

## 当前能力边界

- 已实现情绪的有界事件响应与时间恢复；没有实现对普通语言语气的情绪猜测。离线不产生被冷落或被抛弃的经历。
- 睡眠当前使用确定性归档，能保持事实来源与游标一致；模型自动提取复杂人物关系、世界认识、自动技能提案及长期气质学习仍需后续评估。
- 检索使用中文词项和关键词；语义向量、OCR、语音、视觉与可启动 Linux 不在本版内。
- 文件整理只处理指定目录的普通文件，不递归搬动整个磁盘。恢复原件占用额外空间，清理需单独处理。
- 适配并验收的是 OpenCode legacy HTTP API。V2 API 明确标为不支持，不能把接口握手视为未来版本的兼容承诺。
- 工具权限由执行引擎执行；亲密程度、情绪与经验不能扩大授权。
- 底层测试使用真实程序和本地确定性模型验证执行协议；实际大模型的中文记忆提取质量与人格体验仍需日常任务评估。

## 开发与验证

需要 Bun 1.4.2，Windows x64。依赖版本在 `bun.lock` 固定。

```powershell
bun install --frozen-lockfile
bun run typecheck
bun test
```

在部分 exFAT 环境中，Bun 原地更新 lockfile 会报 `EINVAL`。已有锁文件使用 frozen 模式；需要生成新锁时在 NTFS 临时目录生成并核对后复制，不修改系统配置。

开发启动：

```powershell
bun run src/main.ts --portable-root F:/codex/xingyao/.local/portable --host-root C:/Users/LT/AppData/Local/Xuanji-Development --engine <候选opencode.exe绝对路径> --no-open
```

`--offline` 可以运行资料、记忆、文件整理等功能。所有开发测试使用临时身份和目录，不能指向原用户数据库。

真实引擎测试默认读取 `dist/xingyao-<version>/opencode.exe`。也可设置 `XINGYAO_TEST_OPENCODE` 指向明确候选；缺少真实制品时的 skip 不构成发行验收。构建：

```powershell
$env:XINGYAO_BUILD_ENGINE = '<候选opencode.exe绝对路径>'
bun run build
bun test
```

发行必须包含真实后端契约、恢复与产品流程验收报告，并绑定 `release.json` 的 SHA-256。`script/install.ts` 只接受通过报告的候选，独立暂存后切换发行选择，不覆盖已运行制品。权威选择记录采用追加式完成日志，`current.json` 是便捷镜像。

`src/cli.ts` 与 `src/launcher-cli.ts` 是主程序和启动器的独立编译入口。本机 Bun 1.4.2 的 Windows standalone 制品中 `import.meta.main` 返回 false，因此不能只靠该标志启动程序。Windows 后台启动器会持续持有主程序，直到主程序退出，避免提前退出连带终止子进程。编译产物的 `--version`、真实启动入口和完整启动恢复必须实测。

## 代码边界

| 模块 | 职责 |
| --- | --- |
| `store.ts`、`affect.ts` | 身份、经历、状态、记忆修订、任务与确定性睡眠 |
| `knowledge.ts`、`learning.ts` | 有来源的资料检索、经验候选与撤回 |
| `adapter.ts`、`engine.ts` | OpenCode 公开接口、进程隔离与版本能力检查 |
| `checkpoint.ts`、`engine-backup.ts` | 一致快照、完整代次、恢复与分叉保护 |
| `recovery.ts` | 领域库与引擎库的配套恢复日志、故障续接和旧数据保全 |
| `files.ts` | 文件预览、校验搬移、保全原件与撤销 |
| `releases.ts`、`launcher.ts` | 制品校验、受测切换、配套数据回滚 |
| `server.ts`、`web/` | 本机认证 API、工作台与唯一执行路径 |

引擎的必要补丁、构建依据与退出条件见 `docs/opencode-patches.md`。上游 MIT 许可随发行保留。
